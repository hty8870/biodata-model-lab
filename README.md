# BioData Model Lab

BioData Agent 中轻量学习组件的研究记录与可复现工件：**检索融合排序、工具加载分流、记忆关系判断**。

本仓记录的是问题如何被定义、实验怎样改变决策，以及哪些结果没有站住；不是只展示最终最高分的模型展柜。代码来自实际训练与评测，模型、数据、预测和配置按实验版本登记。产品代码见 [BioData Agent](https://github.com/hty8870/biodata-agent)。

## 三条研究线

| 研究线 | 要解决的问题 | 模型与主要演化 | 阅读入口 |
|---|---|---|---|
| 检索融合 LTR | 词面与向量得分不在同一尺度，如何在硬过滤之后融合排序？ | 规则融合 → GBDT/RankNet → 多模型代理标签 → OOD 混合训练 → 生产特征同源化 | [LTR：设计、数据、实验与边界](docs/ltr.md) |
| 工具分流 | 不值得每轮都请大模型决定是否加载写工具、是否预取检索 | 字符 n-gram 线性模型 → Qwen LoRA → 双判官 → 软标签蒸馏与量化 → 灰带仲裁 | [分流：从分类准确率到槽位收益](docs/routing.md) |
| 记忆关系 | 新倡议与旧记忆的关系，能否由小模型可靠判断？ | 七类混合标签 → 五叶语义关系/双向NLI → 动作三类/细监督对照 → 基座对照 → 原子关系三类 → 自然/反事实强化 | [完整研究演化](docs/memory-relations.md) |

## 先读这三个区别

1. **高分可能来自问题变简单，而不是模型变聪明。** 五叶方案在有限集合模拟中接近满分，在真实文本代理集上却失败；二者不能放在一张榜单上解释为进步或退步。
2. **标签更一致，不保证训练后的排序更好。** LTR 的多模型共识修正了评价尺度，也缩小了早期方法差距；真正有用的后续问题转向了 OOD 和实际触发面。
3. **少调用大模型，不等于更安全或更省总成本。** 路由的覆盖率必须与条件错误率同报；关系模型的高置信错误仍可能漏过。模型输出不授予写入、删除或替换权限。

## 结论的适用范围

这是一个学习型项目的探索性研究档案，不是同行评审论文或通用NLI排行榜。合成文本、程序oracle、AI作者标签、独立AI复核和公开人工参考是不同证据层；没有真人金标的阶段会明确标注。旧报告中的结论如有修正，以本仓分阶段说明和对应机器结果为准，不追溯抹掉失败。

研究候选、历史接入和已验收线上状态分别登记。后期 Qwen/原子关系模型的域内高分，不自动意味着它们已经替换产品中的五叶模型。
