# LTR：从不可比的召回分数到可审计的融合排序

## 1. 为什么训练一个排序器

检索先执行硬条件过滤，排序只在存活候选内进行。词面分数和向量余弦不是同一量纲；把它们分别排序再按比例截断，或做归一化线性融合，并不自动得到更好的最终列表。学习排序的目标是根据检索时确实可得的信号，学习候选间的偏好，而不是让大模型代替硬约束。

初始对照是生产已有的线性融合（α=.5）和RRF（k=60），另保留纯词面顺序。选择小型RankNet而不是在线神经交叉编码器，是为了把训练成本留在离线、在线仅处理九维特征。

## 2. 没有真实反馈，先建立可解释的数据链

| 环节 | 做法 | 设计理由与实际发现 |
|---|---|---|
| 确定性构造 | 受控实体约束组合、9种模板、真实检索取前12候选 | 先确保样本有语料支撑；1254查询、12711个查询–候选记录，不把模板改写当新独立问题 |
| 划分 | 429个约束簇整簇分配，train1103查询、heldout151 | 同一语义组合的改写不跨训练/测试 |
| 自然化 | LLM改写，解析语义校验，失败保留原句 | 1186/1254通过；68条拒绝保留。校验暴露解析器语域狭窄，同时也对训练分布施加选择偏差 |
| 两种标签 | 约束满足度grade∈{0,1,2}；语义相关性∈{0,1,2,3} | 确定性要求与语义偏好分列，避免用一个代理分数掩盖硬条件 |
| 向量增广 | 复用生产查询扩展和候选序列化，本地MiniLM嵌入 | 纯约束标签下词面排序已满分，必须加入真实向量信号才能研究融合 |

这里的“pair记录”与RankNet的“候选偏好对”不是同一计数。现役工件记录1361个训练查询、39117个候选偏好对；旧报告另报15155个候选，不能混成一个数据量。

自然化时被解析器拒绝，不表示用户需求无效。这是生成流程和解析器的限制；因此后续增加独立语域/OOD观察，而不是用模板高分证明自然查询已解决。

### 教师身份纠正

早期把`deepseek-chat`当较强参照、另一个flash别名当廉价候选。实际接口核查发现两者回显同一`deepseek-flash`服务模型；未显式控制的解码/思考默认也不同。因此150对校准里的±1一致率96.0%、0/1边界一致78.7%，只能说明两种调用配置的差异，不能宣称完成了强弱模型能力校准。

这一纠正随后推动异构模型交叉评分：151查询的1400个heldout候选由五个模型独立给分取中位数，训练侧则以小型竞标选择便宜三模型组合。它们仍是**AI共识代理标签，不是人工金标**。

## 3. 模型、特征和控制

RankNet MLP结构为`9 → 32 → 16 → 1`，ReLU，pairwise logistic loss。另训练pointwise HistGradientBoosting对照；训练随机种子20260910。

九维输入为词面归一分、向量分、向量可用标记、候选倒数位次、物种/组织/疾病/原始数据匹配标记和原始数据要求。以实际`ltr_spec.json`的顺序及归一统计为准。标签、教师评分、数据划分和样本编号不能进入特征。

主标签：`0.5 × grade/2 + 0.5 × semantic/3`。同时保留纯约束、纯语义目标，做constraint-only、+lex、+vec消融。打乱候选输入顺序后分数不变，另用反转顺序检验评分器区分度；导出后独立重载核对数值。

## 4. 哪些结果改变了决策

### 模板留出：先证明胜过现有融合，不急着宣称大增益

初始151查询、混合代理标签：

| 排序 | nDCG@5 | nDCG@10 |
|---|---:|---:|
| 词面顺序 | .9608 | .9768 |
| 线性融合 | .9498 | .9634 |
| RRF | .9208 | .9511 |
| GBDT完整特征 | .9688 | .9812 |
| RankNet完整特征 | .9725 | .9816 |

主要负结果是朴素融合可能稀释约束对齐信号；学习器相对词面的改善温和。仅凭这一表不能证明它优于纯向量，也不能证明缺向量候选的任意混合比例已被覆盖。

### 更换评测标签：分数提高可能来自尺子变化

多模型共识下，同一个词面排序的纯语义nDCG@5从.8960变为.9691。混合目标的共识评测中，词面为.9861，使用新标签训练的RankNet为.9871；旧标签训练版在同一新评测上为.9906。

因此：

- 评测标签的变化解释了比模型变化更大的分数差；不能把两张表纵向相减当作模型进步。
- 标签一致性显著改善，不保证训练后的排序继续改善。天花板、偏好对梯度和已有约束特征都可能参与，不能凭结果单独确认原因。
- 后续资源转向OOD与使用场景，不反复打磨接近满分的模板集。

### OOD混合训练：把泛化问题放到训练设计里

在258个OOD查询的五折研究中，每折用模板训练集＋该折允许的OOD训练部分，比较相同候选与评价标签：

| 方法 | OOD nDCG@10，五折均值 |
|---|---:|
| 词面位次 | .7112 |
| 线性 / RRF | .7812 / .7958 |
| 纯向量 | .8510 |
| 仅模板训练LTR | .8627 |
| 仅OOD训练LTR | .8743 |
| 模板＋OOD训练LTR | .8926 |

这支持在该合成分布下混合训练有价值，不是自然用户收益证明。最终混合制品于2026-09-14进入召回融合默认路径；在健康结果列表上无条件重排仍可能伤害结果，不能将“坏结果切片上的优势”推广成全场景重排。

## 5. 后续方法修正：训练数据不是永久测试集

自动转正管线后来发现，原OOD文件既被混入训练又被用于候选裁决。于是按查询ID固定拆成345查询的trainable部分与175查询的eval-only部分。旧现役模型此前看过整份文件，这一历史不能通过重新命名抹掉；新候选与旧现役的比较因此偏向旧模型，必须明确披露。

另有两项实际修正：

1. 用未舍入margin判断胜负，避免极小负值四舍五入为`-0.0`后误放行。
2. 决定性训练固定线程和种子；将生产/训练特征提取收敛为同一函数。默认候选配方的更新不等于现役工件已经重训。第一次新配方候选因OOD门未过而保留，没有为升级版本改门槛。

现役登记仍为`20260914T002354`。它早于正式注册/转正管线，数据指纹和历史门账有缺失，注册表保留null；本仓不补造旧证据。

## 6. 可以复用的方法与尚未证明的部分

可迁移的是：语义簇隔离、约束与语义标签分离、教师实际身份核验、固定候选上的同尺比较、候选偏好对与查询–候选记录分账、训练/生产特征同源、可拒绝升级的转正流程。

未证明的是：真实点击偏好、在线用户收益、任意语料缺向量比例下的稳健性，以及LTR普遍优于纯向量。这里的“heldout”和“OOD”是具体构造与曝光历史，不是独立性或难度的自动保证。

训练源码、冻结数据、指标原件、制品SHA与缺失字段见模型目录和复现指南；后续LLM查询改写实验不冒充LTR重训收益。
