# 记忆关系模型：从七类处置标签到原子关系判别

## 阅读地图

1. 为什么做与七类原型；2. 数据重建与第一次终评；3. 五叶关系和公开NLI；4. 从模拟到文本；5. 206题审计；6. 动作三类与六叶对照；7. 拟合诊断和基座更换；8. 原子化与新三类；9. 同模型前后对照；10. 冲突强化；11. 与LLM配对；12. 记忆披露与当前边界。

这不是“七头→五头→三头，越训越好”的单调升级史。中间改变过任务、表示、数据和评测；若不把这些拆开，满分模拟和低分自然文本会被错误拼成一条曲线。

## 1. 为什么训练：把便宜判断从昂贵编辑中拆出来

记忆学习会不断提出新偏好、规则或技能。每次都用LLM读所有旧记忆、判断关系并规划改写，成本和延迟较高。轻量判别器的初衷，是先研究能否承担其中的关系判断；并非把记忆系统的来源核验、权限、更新意图和持久化事务一起交给分类器。

早期七类继承自维护接口：

| 类别 | 原先含义 |
|---|---|
| complement | 兼容补充 |
| duplicate | 要求等价、重复 |
| conflict | 同对象同条件下不能同时满足 |
| contextual | 有明确条件差异的并存 |
| temporary | 只限一次或有限时间 |
| supersede | 有明确持久变更/撤销依据 |
| uncertain | 关键判断信息不足 |

原型比较多数类、字符逻辑回归、冻结MiniLM特征＋线性/MLP，以及联合编码后微调。初始构造只有16个语义根，却派生出2522行；行数不是独立语义数量。早期特征中的tier/permanence会泄漏构造先验，随后被移出学生输入。教师失败、机械权限拒绝和标注争议也不能一律塞成uncertain。

七类的关键缺陷是混轴：同一条倡议可以同时“临时、重复、拟替代”，作用域和权限又来自上游。把它们压成互斥softmax，会迫使模型学习接口约定，而不是单纯内容关系。

## 2. 数据重建：先纠正评价单位，再相信更大的数字

重建计划预先分配400根、20个作者和train/dev/calibration/heldout/OOD；作者生成5017行，经契约检查、独立AI复核和裁决形成冻结训练与终评。标签始终标为AI代理参考，不改称人工金标。

主对照：旧原标、旧修标、新裁决数据，各3个seed；同400次更新、有效batch16，每50步按根等权dev loss选点。旧两臂文本相同，较适合研究修标；新数据还改变了根数、场景和难度，只能解释组合方案的效果。另做60/120/235根规模曲线，不用它们再次挑最终模型。

| 主要记录 | 数值与含义 |
|---|---|
| 新训练集 | 3290行、235根；共享dev405行、40根 |
| 正式终评 | heldout445＋OOD427，共872个请求；871个有可评分参考 |
| 根宏F1 | heldout .752281；OOD .819548 |
| 有参考行符合度 | 667/871＝76.58% |
| confirmed／全部计划请求 | 667/872＝76.49% |
| 校准/风险认证 | 无可行点，threshold=null；不是“风险为零” |

OOD高于heldout不自动说明标注错了；这两批构造、根和难度不同，OOD并非数学上必须更难。更值得检查的是标签、成员、构造风格和置信区间，而不是要求分数满足某种大小顺序。

pair分类、跨批集合聚合、引用合法性与最终编辑成功分别评测。旧集合诊断只有10个pair具有完整参考，不能把整组标签复制给其余1434个pair。曾错误剔除accepted uncertain的统计也被修正：它是第七类，不是缺标。

## 3. 五叶重设计：语义关系与编辑动作不应混为一谈

在共同解释域、双方非空可满足的集合语义下，两个对象有五种互斥完备关系：

- equivalent；
- old_entails_new_strict；
- new_entails_old_strict；
- disjoint；
- overlap_incomparable。

这让“内容关系”与临时性、作用域、替代意图、权限和不确定解析分开。未提及的旧义务默认保留；局部融合还需定位修改位置并验证保留内容，不靠一个关系标签直接批准整替。

### 与公开三类NLI的联系

固定old=P、new=H方向：equivalent与old-strict映射entailment，new-strict与overlap映射neutral，disjoint映射contradiction。交换方向后，五叶对应EE/EN/NE/CC/NN五个合法组合。这是题定语义模型中的规则关系，不意味着任何自然文本都能被正确解析为集合。

因此可以比较单调用五叶联合输出和双向三类NLI，但必须用相同数据、骨干、预算与评价视图。七类业务模型和另一个在公开NLI数据上训练的三类模型，不能用一次硬映射就变成纯架构对照。

### 先做有限集合模拟，而非直接把复杂文本当真值

在10个可能世界、1023个非空集合组成的1,046,529有序对上，比较粗三类、五logit粗监督、五叶细监督和分层头。配对种子、批序、初始化、选点和最终一次评分先锁定；非法双向组合不修成正确答案，而是留在失败分母。

有限域final中，五叶单前向的fine macro-F1均值约.99220，双向硬恢复强基线约.99332。默认五叶由预注册选择规则保留，**不是全指标胜出**。这些数字来自位图/程序oracle，不是自然语言、真实用户或线上关系准确率。

## 4. 真实文本：表示、监督与公平性开始成为瓶颈

随后将五叶移到真实文本代理语料，对照C5和共享三类模型的双向dual3。早期表示与JSON树表示各做两臂×三seed，共12个主模型，每run固定250更新。每个seed从对应原始母模型出发，不继承旧七类或单独给一臂公开预热；C5复制母输出的父行并减log叶数偏置，保证零步父概率相同。

每批固定16 public＋16 fine，编码两向共64个输入；public仅监督有gold的原向，fine两方向先平均，再按来源各占一半。C5在公开粗标签上用分组概率和损失，不伪造细标签。微批8 oriented×累积8，骨干LR2e-5/head1e-3、AdamW、wd.01、clip1、dropout.1、384窗口，固定50更新检查网格，按共同父NLL选点。推理元数据里的batch_size=16不是这套训练有效批次。

独立fine终评为206根／43簇，12次全部完成；三个seed均值如下：

| 表示／头 | accuracy | fine macro-F1 |
|---|---:|---:|
| 早期表示C5 | .1861 | .1345 |
| 早期表示dual3 | .2573 | .1437 |
| 树表示C5 | .2104 | .1460 |
| 树表示dual3 | .2557 | .1406 |

树表示把开发514根的完整输入从386增至414、39组方向编码碰撞归零，独立206根的完整输入从20增至68；涉及新表示的核心质量比较区间仍均含0。机械完整性改善没有自动变成可证实的学习增益，也不能据区间含0声称等效。

公开评测原计划60次视图运行，实际按明确的行政收缩保留六模型×五view共30次，另30次未执行，不补写完整矩阵赢家。六模型消费同一45528个官方非train行，其中42478有gold、3050缺标；只有早期C5三seed齐全，树表示只留C5-seed13。后者OCNLI/ANLI/HANS/ContractNLI全文accuracy约.3166/.3358/.4974/.4377。ContractNLI某oracle条件任务约.8246的高分主要是多数类：在同1802题、同E/C规则下，全文全判E也有.8252，不能冒称证据定位成功。

暴露审计提供了比“教师一定太差”更具体的假设：prepare虽有131388行，树表示selected100实际只见1600个不同public训练行（117785行的1.358%），另有1600次fine抽样覆盖401根。它们不是terminal250的全部曝光，也不是充分学习的保证；小暴露是候选解释，不是已证低分原因。

后续还分别比较公开训练来源的原生三类与自建文本来源的三类/五叶，以及最终五叶层的交换一致性。不同训练来源独立登记，不拿“多头不适应三类题”或“公开三类更高分”替代归因。原子三类后来又换了任务定义，见§8。

工程保真和语义效果必须分开：独立重载概率差为0，证明保存/加载没有改变输出，不证明原输出正确。运行包可搬迁、输入更完整、软件检查通过，也不预支为模型质量晋级。

## 5. 206题审计：先把失败展示出来

部署过的V3 C5 seed13在206个冻结代理文本对上的审计：与参考一致46/206，macro-F1约.148；严格包含类预测163/206，等价0/33，交换一致48/206；0/206达到当时0.80阈值。

它的accuracy低于多数类常量72/206，但macro-F1高于该常量，不能说“所有指标都更差”。此后不再把已看过的206题叫盲测，也不据它重新挑seed。

训练内诊断进一步发现原train正向172/401、dev34/113；完整输入子集也弱，不能只归因于OOD或截断。这推动了下一阶段：先核loss、输入和拟合能力，再讨论输出头或基座。

## 6. 第一个动作三类：减少输出，不等于解决任务

直接预测`coexist / replace_all / merge_preserve`更贴近维护动作，但旧五叶并非它的严格细分：同一disjoint可以发生在整条记忆，也可以只发生在复合记忆的一部分。这里`merge_preserve`是动作类，`merge_conflict`是六叶方案里的细类名，不能混作同一个类别序。

为公平研究“细监督是否帮助粗任务”，另建严格嵌套F6：四种共存关系子类＋整替＋局部融合；共同评估最终动作。A3/F6共享初始化动作概率、完整输入、300更新/9600实例和dev动作macro-F1选点。F6仅多1155个参数，不能把差异简单讲成“多头耗尽模型容量”。

受控文本1200对（720/180/300），有限槽位oracle。最终发现一对dev/验证在文字不同的情况下语义等价，于是固定所有权重，另生成一次去逻辑重复的300题确认，原结果不删。

| 确认300题，两seed均值 | A3 | F6 |
|---|---:|---:|
| macro-F1 | .40497 | .43666 |
| accuracy | 45.00% | 45.33% |
| 误整替丢旧信息／150 | 69 | 43 |
| 未处理冲突／200 | 20 | 26.5 |
| 额外融合／200 | 45.5 | 72.5 |

细监督有窄方向收益，却用更多LLM融合换取更少信息遗失；不是全面胜出。类内随机细标签、mean读出和浅基线对照也没有给出稳定的细语义归因。

进一步的六维粗监督机制分析发现：复制初始化且只监督聚合三类概率时，四个共存子头可永远保持相同；理想更新可与普通三类等价。实际梯度裁剪可能改变轨迹，但不凭空赋予细语义。对称破缺后的新最小变化题仍很弱，因此没有继续为增加维度而堆训练。

## 7. 更好的三类来自哪里：拟合诊断与基座对照

固定数据、标签和划分，先检查同输入异标、截断、loss/target、优化器漏参、梯度和实际参数更新，再延长MiniLM训练。900更新时720/720训练全对，dev最优却在400步，后续继续过拟合。结论是**可以拟合，但没学会稳定泛化**，不是“标签再差也不影响是否有用”。

比较替代配方：MacBERT-base全参、Qwen3-0.6B LoRA，各固定300更新。120题最小变化诊断的macro-F1分别约.7554/.8929；Qwen第二seed又在新20族120题上达到104/120、macro-F1 .86621，第一seed为98/120、.80114。

替代方案值得继续，但这不是纯架构因果：tokenizer、读出位置、全参/LoRA、token曝光和原MiniLM预算不同。不同错误也有取舍；更高F1不等于更少不安全整替。

## 8. 原子知识库下的新三类：与动作三类不是一回事

将“回答用英文，公式用LaTeX”在提案时拆为可独立维护的义务，期望关系判别更简单。此时训练目标改为：

| 原子关系三类 | 语义 | 不自动意味着 |
|---|---|---|
| equivalent | 要求等价 | 允许删除任意旧条目 |
| compatible | 不等价但可同时满足，含单向包含 | 绝无冗余、永远无须维护 |
| conflict | 同共同适用域内无法同时满足 | 新条目必然有权取代旧条目 |

单向包含被归入compatible，会留下冗余风险；原子化也不能替代来源、条件和跨条目一致性。无旧项由确定性逻辑处理，复合冲突和编辑仍可交LLM。

新的同数据对照是direct3与fine5→三类。旧文本514行加70个scenario family/1050对，最终train1001、dev263、cal150、heldout150。heldout三类模板组合已出现在train，且作者分配与split混淆，不能叫全新关系或完整作者留出。

两臂共享Qwen3-0.6B、300更新、seed13/42、LoRA r16/alpha32、max_length768；仅保存adapter/head，不存Adam或重复基座。

| 150题代理留出 | direct3，两seed均值 | fine5，两seed均值 |
|---|---:|---:|
| accuracy | .96000 | .94667 |
| 三类macro-F1 | .95256 | .93853 |
| conflict recall | .95000 | .96667 |

direct3更简洁且均值更稳，但fine5在seed13反超，并有不同误等价/漏冲突取舍。相对旧线上模型的成倍分数提高不能全算输出头功劳：基座、数据、输入与训练目标都已改变。

## 9. 原子化是否伤效力：必须固定关系模型再比较

先前抽取pilot比较现有方案、直接原子化和二次原子化。第二次加工未稳定恢复coverage，且调用更贵；换Qwen27B提升了faithfulness和完整集合比例，却降低coverage，不能把一个指标升高称为全面改进。

同模型配对研究固定50族150例，对比：A原复合文本、B规格原子、C真实LLM拆出的原子。C−B才较接近真实抽取附加效应，B−A同时含表示与聚合变化。

C相对B的accuracy差为seed13 0、seed42 −0.67pp，但预定整体非劣证据不足，不能据接近0的点估计宣布“效力未减”。合法更细划分也曾被“一侧一槽恰好一个原子”的结构规则误记invalid；后续将结构准入损失、抽取保真与关系误判分开，避免把评分器假设当作模型错误。

## 10. 冲突强化：等量自然数据、反事实组织与额外损失

保持三类与Qwen3-0.6B，新增60族1080对；每臂训练1289对，300更新，seed13/42。R0是旧direct3的对应末步，不是早期BERT或多数类常量。

| 臂 | 新数据／目标 | 想隔离的因素 |
|---|---|---|
| R1 | shared＋等量自然表达，CE | 普通数据增强 |
| R2 | shared＋反事实dyad，CE | 近邻边界训练组织（仍混有语义新颖度等因素） |
| R3 | 与R2同数据，CE＋间隔损失 | 额外目标；同初始化、窗口与token预算 |

主比较统一terminal-300，不用早停点掩盖预算差。自然留出288题、反事实144题、旧150题与公开诊断分开报告。

- **R1自然题更稳**：两seed均281/288正确，冲突95/96、94/96。
- **R2边界对更好**：反事实dyad两侧全对65/72、68/72；等价↔共存均24/24。
- **R3没有稳定收益**：seed42自然题相对R2新错12、纠错1；不能只展示seed13。
- **公开迁移仍弱**：OCNLI的1502个有gold诊断里，新臂没有跨seed稳定矛盾召回改善；R1-seed42甚至从R0的227/452降到132/452。

预定“两seed冲突召回均增加10pp”还暴露设计错误：R0-seed42起点93.75%，最多只能提高6.25pp。原未达标判据保留，但不能据此说所有增强无效。方法论改进包括分别核验生成语句是否忠于预定义务、标签是否符合实际文字；异模型关系一致并不能替代前者。

## 11. 与LLM同题比较：优势主要在常驻GPU速度

固定R2两seed，在同432个已曝光代理记忆对上对比实用flash级LLM；另取144个公开诊断。两者都是三类关系判断，不把LLM要求成更难的编辑任务。

| 432题方案 | 正确 | macro-F1 | conflict FP/FN |
|---|---:|---:|---:|
| R2 seed13 | 410 | .94890 | 3 / 12 |
| R2 seed42 | 418 | .96747 | 3 / 6 |
| LLM逐对 | 408 | .94338 | 19 / 0 |
| LLM匿名8对批 | 423 | .97906 | 6 / 1 |

原批编号与gold关联，修正后保留正文、顺序、分组和提示定义，重新用匿名编号补采；原424/432不是干净基线。匿名批还会看到另外七段正文，不能当纯单对能力消融。

同36道记忆题，常驻GPU的R2 p50约114ms，API串行约871ms；双线程CPU约778ms，尾延迟不更好，进程加载另约7.70–9.47s。公开144题上LLM正确119，R2为104/102；不能宣称通用语义胜出。

0.80离线级联虽能减少域内98%以上关系分类LLM请求，却留下高置信错误；不是安全证书，也不是整个学习环节省98%。token缓存、批次上下文、硬件驻留、训练和维护决定真实成本，少调用不自动等于总成本低。

## 12. 记忆能否被读到，与关系分类是另一条问题

后续比较全文段落、全文原子、预算原子检索、图扩展和编译视图。校正评分器过度历史引用要求后，有限题集上的最低充分动作/值与依据投影有改善；这是同一回答离线重评，不是模型变强。部分投影不检查条件/例外，不能叫完整语义正确率或统计非劣。

项目进一步加入分类目录和按需正文披露。分类是组织与检索手段，不证明不同类互斥，也不能据类名不同免做冲突检查。这是记忆访问架构，不是新一轮关系模型训练。

最后有部署证据的产品模型仍是V3 C5 seed13及0.80阈值。后续动作三类、Qwen、原子关系和R1/R2/R3属于研究候选；本仓公开它们不等于生产替换。

## 可以带走的方法

以最终任务对齐监督和选点；先做拟合/输入/梯度诊断再谈容量；固定模型研究表示变化；将语句保真与标签正确分开审核；区分同模板留出和真正域外；按语义簇而不是派生行估计不确定性；同时报告漏冲突、误等价、信息遗失和额外融合；把风险认证失败、无收益的复杂目标与测量器错误都作为结果保存。

模型卡、完整配方、数据、逐题结果和来源清单提供细节。没有保存权重的纯机制检查会明确列为“未训练／未落盘”，不伪造一个可下载模型。
