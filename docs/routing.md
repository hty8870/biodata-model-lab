# 工具分流：小模型应当占据哪个决策槽位

## 1. 起点不是“用小模型替换整个Agent”

原系统每轮用LLM投票判断search/action/general，并提前启动本地检索。闲聊、概念问答和管护请求也可能先支付检索与嵌入开销。

真正要回答的是两个较小问题：

- **binary写工具加载**：这句话是否需要产生下载或数据写入后果的工具？分类只决定工具可见面，不批准写入。
- **prelim检索预取**：是否值得在Agent正式行动前启动本地检索？误跳过与误起跑的代价不同。

原三分类保留为兼容研究/兜底，而不是强迫所有决策共享一个“准确率最高”的模型。

## 2. 第一阶段：先做便宜、可导出的线性基线

L0采用字符TF-IDF（2–4gram）＋逻辑回归。sklearn用于训练，vocab/idf/coef/intercept、温度和工作点导出为JSON；纯Python执行相同前向，不把训练依赖带入关键路径。导出与训练端的概率差曾实测不超过4.4e-16。

初始2393条合成查询由LLM共识打标，按60/20/20分层拆分。阈值一度在test上选、又在test上报告；后续明确改为cal选工作点、test只报告。留出成绩是教师符合度，不是人工正确率。

两个槽位采用不同准则：

| 槽位 | 优先避免的错误 | 工作点选择 |
|---|---|---|
| 写工具加载 | 错误限制需要的工具或无谓升级 | 高置信直采，其余回LLM；保留请求换线的逃生口 |
| 检索预取 | 应检索却误判skip | calibration上设retrieve召回下限，而非追求总体accuracy |

L0常驻单次推理为微秒量级。初期同分布测试很好，但108条拼音、英文、取消动作、指代等构造OOD上，二元准确率87.0%、检索准确率73.1%，并出现接近1的自信错误。**蒸馏忠实不等于语域泛化。**

## 3. 公平比较：先把数据增广给双方

增加680条拼音、英文、口语、边界和否定增广；构造继承标签，不调用LLM。L0+aug与神经模型共享相同训练来源，避免把新模型的收益全部归因于容量。

OOD二元准确率由87.0%升至94.4%，检索准确率由73.1%升至85.2%。这一对照先证明数据覆盖本身就能贡献很大提升。

108条OOD未直接作为训练行，但后续灰带参数优化使用过其指标。因此本仓将其标为**构造OOD开发诊断**，不能继续称作完全独立终测；文件名中的`ood`不改变曝光历史。

## 4. 从Qwen LoRA到双判官：利用错误互补

早期神经臂使用Qwen2.5-0.5B-Instruct＋LoRA。输入为任务定义和一句请求，在答案位置只对候选词token取logits；一次前向给类型化选项分数，不生成长推理。这借鉴了System-One式接口，不是官方Jev模型或其训练过程的独立复现。

| 变化 | 结果与后果 |
|---|---|
| 瘦prompt、r8、2epochs | OOD写闸91.7%，检索69.4%；不达目标 |
| 明确边界/否定/指代定义、r16、3epochs | 写闸约94.4%–95.4%；检索召回仍只有.74，不能直接守检索闸 |
| 与L0+aug交叉观察 | 单体会错，但不总错在相同题；形成外部不确定性信号 |

前代配置的一致子集：OOD96/96正确、覆盖约88.9%；ID一致子集604/605正确。它是**选择性子集的经验结果**，不是全量准确率或风险保证；两模型的标签来源也不独立。

据此采用“两个廉价判官一致才采纳，分歧升级LLM”。模型缺席时退回单模型工作点，再退回LLM；不把缺依赖变成服务单点。单纯把一个softmax阈值调得更高，不能保证捕捉相同的外部盲点。

## 5. 训练法与基座分开：硬标签CE和软标签KL

后续做2×2对照：Qwen3-1.7B／Qwen3.5-2B × 硬标签CE／软标签蒸馏。软目标来自同任务prompt下教师多次采样的选项频率；这里的RLCD实验是**监督式分布蒸馏**，不是在线策略强化学习。

Qwen3-1.7B两臂的共有配方为lr1e-4、2epochs、seed20260919和共享行划分；训练任务收敛为binary/prelim。完整LoRA参数、数据成员、温度和工作点随工件保存。

| 指标 | 1.7B CE | 1.7B KL | 2B CE | 2B KL |
|---|---:|---:|---:|---:|
| binary ID accuracy | .9854 | .9789 | .9854 | .9772 |
| binary OOD accuracy | .9444 | .9444 | .9259 | .9444 |
| prelim ID accuracy | .9724 | .8358 | .9707 | .8764 |
| prelim OOD recall | .84 | .94 | .82 | .86 |
| prelim OOD正确skip比例 | .759 | .586 | .828 | .621 |

软目标可能降低对硬参考的argmax符合度，同时在所选召回工作点上少漏检索；代价是更多起跑。**这不是全指标胜出。** 温度更接近1也不等于校准更好：相对硬参考的未校准ECE没有一致改善，早期报告里据此宣称“赢校准”的说法应撤回。

量化还改变了排序：Q4下，KL臂的binary OOD下降约3.7pp，CE臂约0.9pp。可能涉及margin变薄，但没有表征层因果实验证明。应在目标量化精度和实际运行栈上验收，不能拿未量化GPU结果替代CPU成品结果。

## 6. 同一模型，不同槽位可以需要相反组合规则

对binary，双判官一致是可用的升级信号；对prelim，直接套同一规则却失败。研究比较了双官一致skip、任一官retrieve等规则：前者会伤召回，后者减少了可跳过的检索，均不优于L0单官的原工作点。

最终候选是**灰带仲裁**：L0明显需要检索或明显可skip时立即决定，只让约1.3%的边界请求进入较慢Qwen模型。所报构造OOD上，retrieve recall维持.98，正确skip比例由.741到.862。灰带界限曾依据该OOD选择，所以这是开发结果，尚欠独立终测。

微秒级L0、约百毫秒级GPU神经前向、CPU量化模型的启动/常驻成本不能混为一种“延迟”。灰带的意义是按触发概率摊销较慢判断，不是声称神经网络本身变得与线性模型一样快。历史原件还显示transformers大版本可改变边界判决，生产栈验收必须单列。

## 7. 一个被否决的简化：让模型自己输出escalate

给模型增加第三个`escalate`选项，以教师票分裂度派生软标签，希望替代外部双判官升级。训练后常规ID符合度基本保留，但弃权率为0；原双判官分歧子集上，B3只对13/31和6/12。

这说明**本次标签配方和训练下**，自评弃权没有学会捕捉需要外援的盲区。不能外推为“所有选择性分类都无效”或“外部双判官能保证安全”；小比例弃权质量、任务混合与损失权重都可能参与。该实验没有上线取代一致闸。

## 8. 交付和局限

公开工件覆盖L0各任务JSON、Qwen2.5前代、Qwen3硬/软目标、Qwen3.5对照及弃权实验；冒烟模型另标，不拿它们冒充正式训练。基模与adapter分开，脚本记录候选token、任务prompt、温度、阈值、训练法和数据划分。

产品包含双判官与灰带接线，不意味着任何CPU实例都实际驻留Qwen。实际执行取决于依赖、硬件和配置；研究训练完成、代码接入和服务部署是不同状态。

主要尚欠：独立新分布终测、真实使用频率、跨seed稳健性、人工语义审核，以及含硬件驻留/维护成本的系统收益。轻量模型减少的是特定决策槽位的LLM调用，不是替代Agent的整体理解和授权机制。
